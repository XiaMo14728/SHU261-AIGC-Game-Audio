## 摘要

本项目以"城市公园湖畔步道 · 清晨"为设计对象，完成一次完整的环境声设计实践：从场景分析出发，划分基底与事件两层声景结构；使用 AIGC 音频生成工具制作 1 条 40 秒无缝循环的基底环境声与 4 类共 12 个间断随机声；在 Reaper 中完成剪辑、循环点处理与格式规范化（48kHz/24bit/stereo WAV）；最终在 Wwise 2025.1.11.9262 中构建交互音频工程，通过 Loop 属性实现基底持续循环、通过 Random Container 实现随机触发、通过 3D Positioning 与 Attenuation 实现随距离变化的听感。

本设计的核心思路是：**用"包围 vs 方位"这一听觉关系来组织素材与技术选择**——包围性的基底做成 2D 无限循环，方位性的事件做成 3D 随机触发。技术配置不是孤立的操作练习，而是场景听觉逻辑的直接结果。

**关键词**：环境声设计；声景；AIGC 音频生成；Wwise；随机容器；3D 定位

## 一、场景选定与说明

### 1.1 场景

**城市公园湖畔步道 · 清晨（雨后初晴）**

一条沿湖的石板步道，左侧是成片的落羽杉和水杉林，右侧是湖面，步道向前延伸约 200 米后拐入林间。时间为工作日清晨 6:30 前后，游客尚未涌入。

（场景照片见附录 A，共 4 张：步道全景、湖岸近景、树林仰视、水面与对岸。）

### 1.2 场景的听觉描述

清晨六点半，雨刚停。石板步道上还留着浅浅的水光。

声音首先是**包围感**的。风从湖面方向过来，穿过左侧落羽杉林，树冠在高处是大片大片的沙沙声，像一整块缓慢起伏的布料；越往下越细碎，到耳边只剩下枝叶相互触碰的屑屑声。这层声音几乎没有节拍，它只是存在，随着风的强弱在几秒到十几秒的尺度上缓慢呼吸。

湖面比树林安静得多。水贴着石砌的护岸轻轻拍打，一下，又一下，间隔并不规律，力道也每次不同——有时是干脆的"啪"，有时只是水体缓缓漫上石缝又退回去的"咕"。这层声音在中低频垫住了整个空间。

再往远处，城市还没有完全醒，但也没有完全睡。隔着湖对岸的树林，能听到一层极低的嗡鸣，是早班公交和环路车流混合出来的底噪。它不构成任何具体事件，却精确地标定了这个公园在城里的位置——这是"城市公园"和"深山湖泊"最本质的区别。

在这一切之上，是**事件**。一只乌鸫在近处起了个头，两三个音，然后停了；隔了十几秒，另一个方向又应了一句。水面忽然"哗"地一声——是白鹭从浅滩起飞，翅膀拍了三四下，带起一串水珠落回湖里，然后就远了。风偶尔会突然压下来一阵，整片林子从远到近被扫过一遍，声音像波浪一样推过来又退走。再偶尔，从步道尽头传来一声自行车铃，"叮铃"两下，清脆、短促、有明确方位。

**基底层是"包围"的，事件层是"从某处传来"的。** 这个观察决定了后续全部的技术选型。

### 1.3 为什么选这个场景

1. **频段层次干净**：树叶摩擦是高频宽带噪声，湖水拍岸集中在中低频，远处城市嗡鸣落在超低频，三层几乎不冲突。这对 AIGC 生成的素材尤其重要——AI 素材往往比真实录音更"平"，需要靠频段分离来支撑空间感。
2. **空间纵深明确**：栈道、湖面、树林、远处城市构成由近及远的四层距离，声音的远近关系可以在听觉上真实表达。
3. **事件辨识度高**：鸟鸣、水鸟起飞、阵风扫叶、自行车铃在频谱与时间形态上差异极大，不会互相掩盖。
4. **天然对应 2D + 3D 架构**：包围层做 2D 循环、事件层做 3D 定位，技术点由场景逻辑推出，而非为完成作业硬凑。

### 3.2 生成方法

音频生成模型的单次出片率明显低于图像生成：同一提示词连生成数次，可能只有一两次可用。因此本项目的流程是 **"抽卡 + 严格筛选"**：每个资产生成 3–5 次，按以下优先级筛选——

1. 没有音乐性（不能出现旋律、节拍、和弦）；
2. 没有人声；
3. 声音形态正确（鸟鸣不能听成犬吠，风声不能听成海浪）；
4. 没有明显 AI 瑕疵（突然截断、无意义电子味、首尾静音块）。

提示词采用"**声源 + 视角距离 + 声学环境 + 时长 + 排除项**"五要素结构。完整提示词清单见附录 B（共 13 条主提示词 + 变体改写说明）。

`⬜ 待填`：实际的生成次数统计（例如"13 个资产共生成 XX 次，初筛可用 XX 条"）。这个数字很能说明 AIGC 素材的真实成本，建议如实写。

### 3.3 一个必须记录的问题：AI 长音频的结构漂移

基底环境声最初尝试直接生成 40 秒，但发现生成结果在 10 秒之后会逐渐"漂移"——开头是稳定的树林风声，到后半段慢慢变成别的环境，甚至混入类似水流的持续音。

最终改用**分段生成 + 拼接**：生成 4 段 12–15 秒，取其中最稳定的部分在 Reaper 里交叉淡化拼接成 40 秒。「让 AI 做短片段，让 DAW 做结构」——这是本次实践中得到的一条可复用经验。

`⬜ 待填`：你实际观察到的 AI 瑕疵现象（越具体越好，这是报告里最有价值的部分）。

## 四、剪辑与格式处理

### 4.1 工具与工程设置

使用 Reaper 7.86。工程采样率设为 **48000 Hz**、位深 **24 bit**，导出格式为 **WAV / 24 bit PCM / Stereo**。

### 4.2 基底的无缝循环处理

这是本次技术难度最高的一步。拼接后的素材总长约 55–60 秒，需截出 40 秒且首尾能无缝相接。

**做法：尾巴叠头交叉淡化**

1. 从拼接结果中选取音色均匀、无突发事件的 42 秒段落；
2. 取该段落最后 2 秒，复制并粘贴到段落开头，形成 2 秒重叠；
3. 对重叠区做 2 秒等功率交叉淡化：复制段淡出、原始段淡入；
4. 从段落起点渲染 40 秒。

因为文件开头是"上一轮的结尾"淡入、结尾是"下一轮的开头"淡出，首尾相接时能量连续，循环处听不出接缝。

在此基础上加 40 Hz 高通滤波去除超低频堆积，整体峰值控制在约 -6 dBFS。

`⬜ 待填`：循环测试的实际结论（是否一次成功、返工了几次、最终用哪种淡化时长效果最好）。

### 4.3 随机声的处理

12 个随机声统一处理：裁掉首尾静音（AI 素材首尾常带 0.2–0.5 秒静音块，会导致 Wwise 里触发有延迟感）→ 加 2–5 ms 淡入淡出防止切口爆音 → 60 Hz 高通 → Normalize 至峰值 -3 dBFS。

### 4.4 自动化校验

为避免人工确认格式出错，编写了 WAV 头解析脚本 `final/tools/check-wav.js`（无第三方依赖，直接读取 RIFF/fmt 块），逐文件校验采样率、位深、声道数、时长，并额外检查"基底是否 >30 秒""随机声数量是否 ≥3"。

## 五、Wwise 工程实现

### 5.1 环境

Audiokinetic Launcher + **Wwise 2025.1.11.9262**。工程名 `ParkLakeAmbience`（不含中文），平台 Windows。

工程目录提交到仓库时通过 `.gitignore` 排除了 `.cache/`、`GeneratedSoundBanks/` 等生成物，只保留 `.wwu` 工程文件与 `Originals/` 原始音频，避免无意义的二进制变更与冲突。

### 5.2 层级结构

```
Default Work Unit
├── Ambience
│   └── amb_parklake_loop_01        （Sound SFX，2D，Loop）
└── SFX
    ├── RC_BirdChirp                （Random Container × 3 变体，3D）
    ├── RC_WaterBird                （Random Container × 3 变体，3D）
    ├── RC_LeavesGust               （Random Container × 3 变体，3D）
    └── RC_BicycleBell              （Random Container × 3 变体，3D）
```

### 5.3 基底的持续循环

对 `amb_parklake_loop_01` 勾选 **Loop** 属性，使其无限循环播放。同时确认该属性的继承关系正确（未被父级 override），Playback Limit 保持 1，确保基底只有一路。

**基底刻意不启用 3D、不绑定 Attenuation**——它是包围性的，不应该有方位。

### 5.4 Random Container 随机触发

四类随机声各建一个 Random Container，容纳各自的 3 个变体，Random Type 采用 **Shuffle（洗牌）** 并启用避免连续重复。相比纯随机，洗牌模式在只有 3 个变体时更能避免"刚响过又响一遍"的重复感。

### 5.5 3D Positioning 与距离衰减

四个 Random Container 均开启 3D 定位，并共同绑定一个 Attenuation ShareSet `ATT_Park_3D`：Max Distance 设为 **50 m**，曲线采用 **Logarithmic**。效果是听者在 0–5 m 内几乎满音量，10 m 起明显衰减，50 m 外基本不可闻。

**定位策略的对照**正是本设计的核心表达：

| 对象 | 定位 | Attenuation | 设计理由 |
| --- | --- | --- | --- |
| 基底环境声 | 2D | 不绑定 | 包围感，无方位 |
| 4 个 Random Container | 3D | `ATT_Park_3D` | 事件有明确来向与距离 |

### 5.6 Soundcaster 测试

在 Soundcaster Session 中分别触发基底的 Play Action 与四类随机声，验证三点：基底循环无接缝、随机声每次换变体、在 Game Object 3D Viewer 中拖动听者位置能听到明显的距离变化。
