一、实践总结

1.1 具体内容

本次基础实践分两个阶段完成。

阶段一（平时作业 Task）：以"当下 AIGC 在游戏音频设计中的应用"为题做调研。从 Voice / Music / SFX 三个方向与 Text-to-Audio / Text-to-Speech / Video-to-Audio / Text-to-Video 等生成模式两条轴切入，梳理了 AIGC 在游戏音频中的落地方式、工程接入路径与权利合规风险，形成约 340 行的调研报告。

阶段二（期末作品 Final）：完成一次完整的环境声设计实践。以"城市公园湖畔步道 · 清晨"为设计对象，从场景分析出发划分基底与事件两层声景结构，制得 1 条 40 秒无缝循环基底与 9 个间断随机声（48kHz/24bit/stereo WAV），并在 Wwise 2025.1.11.9262 中构建交互音频工程，实现基底循环、随机触发与 3D 距离衰减。

1.2 收获

① 建立了"声音可以被结构化设计"的意识。 过去做声音只是"找几个素材贴上去"，这次必须回答：这个场景有几层声音？哪些是包围的、哪些是有方位的？基底里能不能出现鸟叫？这些问题一旦问出来，技术方案几乎是自动导出的。

② 认识到"技术配置是设计意图的结果，不是动作清单"。 作业要求"设置基底循环"和"设置随距离变化"两项技术点。孤立地看它们只是两个操作；但从场景出发就会发现：基底是包围的，所以它必须是无方位的 2D 循环；事件是从某处传来的，所以它必须有 3D 定位和距离衰减。技术点的分工来自听觉逻辑本身。

③ 掌握了从素材到工程的完整链路。 采集 → 格式规范化 → 循环点处理 → 导入中间件 → 配置交互行为 → 验证。每一环都有具体的坑，见第四节。

④ 学会了用客观手段替代主观猜测。 素材挑选与切割边界的确定本可以"听着差不多就行"，但通过频谱分析、包络测量与自动化校验脚本，把大量判断变成了可复现的数据。这一条对最终质量的影响最大。

1.3 对已学理论知识的提高

  • 声景理论：把"基底（keynote）"与"信号（signal）"的区分落实到了具体技术配置上——基底做 2D 无限循环、事件做 3D 随机触发。理论不再是概念，而是可以直接翻译成工程参数的东西。
  • 交互音频架构：理解了游戏音频不是"播放文件"，而是"由游戏状态驱动、经中间件组织的实时系统"。素材从稀缺变为过剩之后，中间件这类"组织与响应"层的重要性反而上升。
  • 音频格式的工程意义：采样率、位深、声道数不是形式要求。本项目素材来自三种不同采样率（48k / 44.1k / 24k），统一重采样的过程让我理解了奈奎斯特频率、重采样的信息损失、以及"24 bit 容器装不下不存在的信息"这件事。
  • 对 AIGC 的再认识：本次使用 AIGC 与素材库，与平时作业的理论分析形成对照，详见第三节（4）与第五节。

轴 覆盖内容

核心结论：

  1. AIGC 在游戏音频中的现实定位是「素材生产与变体供应商」，而非「艺术决策者」；
  2. 离线生成 + 人工精修 + 中间件组织是当前最务实的工程组合；运行时生成受延迟与算力约束，仍属实验性质；
  3. 素材从稀缺变为过剩后，Wwise / FMOD 这类「组织与响应」层的重要性上升而非下降；
  4. 最大的风险不是技术，而是权利与合规；
  5. 评估 AIGC 音频方案应看「平均可用率 + 修复成本」，而不是「最佳样例」。

2. 作品说明

（1）确定设计对象，收集声音素材的过程

设计对象：城市公园湖畔步道 · 清晨（雨后初晴）

一条沿湖的石板步道，左侧是成片的落羽杉和水杉林，右侧是湖面。时间为工作日清晨 6:30 前后，游客尚未涌入。

选择理由：

  1. 频段层次干净——树叶摩擦是高频宽带噪声，湖水拍岸集中在中低频，远处城市嗡鸣落在超低频，三层几乎不冲突。这对质量参差的素材尤其重要，需要靠频段分离来支撑空间感；
  2. 空间纵深明确——栈道、湖面、树林、远处城市构成由近及远的四层距离，声音的远近关系可被真实表达；
  3. 事件辨识度高——鸟鸣、水鸟起飞、阵风扫叶在频谱与时间形态上差异极大，不会互相掩盖；
  4. 天然对应 2D + 3D 架构——这一点直接决定了后续全部技术选型。

声景分层与素材需求：

层 内容 功能 资产
基底 L1 风穿树冠 空间高度与包围感 amb_parklake_loop_01
基底 L2 湖水轻拍石岸 空间实体与空旷感 （同上，双层混合）
基底 L3 远处城市低频嗡鸣 交代城市地理属性 （同上，双层混合）
事件 A 鸟鸣短句 近处生命感 sfx_bird_chirp_01~03
事件 B 水鸟起飞（拍翅） 中距离突发动态 sfx_water_bird_splash_01~03
事件 C 阵风扫叶 打破时间均匀性 sfx_leaves_gust_01~03

合计 1 条基底 + 3 类共 9 个随机声。作业最低要求为「1 条基底 + 3 个随机声」，这里做 9 个是因为 Random Container 需要每类至少 3 个变体才能有效避免机械重复。

素材收集方式

原计划全部使用 AIGC 生成，实际执行中遇到地区限制与现实约束，最终改为素材库 + 客观测量筛选：

  • 基底环境声：取自两个免费素材库录音（Pixabay 的 ambience-wind-blowing-through-trees，Freesound 的 noise-of-wind-in-tree-foliage），双层叠加。
  • 间断随机声（9 个）：取自免费音效库。

⬜ 待填：请补充这 9 个随机声的具体下载页面链接与授权方式。建议格式： bird_01~03 — Pixabay，https://pixabay.com/sound-effects/...（Pixabay 内容许可）

为什么放弃全程 AIGC：长时、连续、无音乐性的环境声恰是当前音频生成模型最薄弱的一环；而素材库里的真实录音自带空间感与微动态。这一取舍本身是一次设计判断——不同性质的声音用不同手段：真实素材提供空间真实感与可靠性，合成手段提供变化量与生产效率。

素材的客观测量（而非凭感觉选材）

对两条基底源素材做了量化分析（MP3 帧解析 + WASM 解码 + FFT）：

指标 主层（traian1984） 副层（freesound）
采样率 / 编码 48000 Hz / 256 kbps CBR 24000 Hz / 160 kbps
左右声道相关性 0.786 0.598
动态范围（5%–95% 分位） 8.31 dB 13.19 dB
瞬态事件（>6 dB 孤立峰） 2 个 0 个
峰值电平 -31.14 dBFS（偏低 25 dB） -3.99 dBFS
频段能量 2–8 kHz 5.4% 62.2%
频段能量 <200 Hz 71.3% 1.4%

两层频段分布的互补性一目了然：主层的短板正是副层的长板。据此确定双层叠加方案，而不是试图用一条素材 EQ 硬调。

选材准则：基底层不允许出现可辨识的离散事件。原因有三——会与 3D 事件层互相打架、会被 40 秒循环周期性暴露、会掩蔽掉真正需要定位的声音。判断方法是把音量降到最终电平连听三遍，若能预期某个声音何时出现，它就是"钉子"。

（2）剪辑素材，导出资产的过程

工具与工程设置：Reaper 7.86；工程采样率 48000 Hz、位深 24 bit。

基底处理链路：

两条源素材（48k / 24k）
  ↓ 副层重采样 24k → 48k（零插值 + 127 抽头加窗 sinc FIR，截止 11 kHz）
  ↓ 各自按窗口切片 + "尾巴叠头"等功率交叉淡化 2 s → 精确 40.000 s
  ↓ 滤波（主层：110 Hz 高通 + 2.5 kHz 高架 +2.5 dB；副层：1.5 kHz 高通）
  ↓ 电平配平（主层峰值 -6 dBFS；副层 RMS 比主层低 15 dB）
  ↓ 双层叠加 → 导出 48kHz/24bit/stereo WAV

循环点处理（本作品技术难度最高的一步）——采用"尾巴叠头"交叉淡化：

  1. 从源素材中选一段音色均匀、无突发事件的区间；
  2. 取该段最后 2 秒，复制粘贴到段落开头，形成 2 秒重叠；
  3. 对重叠区做 2 秒等功率交叉淡化：复制段淡出、原始段淡入；
  4. 从段落起点渲染 40 秒。

这样文件开头是"上一轮的结尾"淡入、结尾是"下一轮的开头"淡出，首尾相接时能量连续。

验证数据：把文件首尾相接，比较接缝处样点跳变与全文件样点跳变的 99% 分位——比值为 0.79×（小于正常波动范围，即无缝）；开头 100 ms 与结尾 100 ms 的 RMS 差 0.2 dB（无音量塌陷）。

随机声处理：9 个随机声统一裁掉首尾静音 → 60 Hz 高通 → 峰值归一至 -3 dBFS → 按类型加淡入淡出（静音间隙处切出的用 60 ms，连续纹理型用 150 ms）。

切割边界的确定（一次事后返工）

最初按能量包络粗略选窗，试听后发现多个文件切在声音中间（sfx_bird_chirp_02 结尾残留半声鸟叫、sfx_water_bird_splash_02 中段混入明显金属碰撞声）。改进做法：

  1. 静音间隙检测：计算 20 ms 包络，标记低于峰值 -30 dB 的连续安静段，只在"安静段结束"与"另一安静段开始"之间取窗，保证两头都在静音里；
  2. 频谱音调性分析：对每个 50 ms 帧计算"前三强谱峰均值 / 谱中位数"，音调性高的帧即存在窄带音（金属声、鸣笛）；据此定位并避开。

修正后 9 个文件的边界复查结果：8 个完全干净，1 个为自然起音（非切割问题）。

（3）使用 Wwise 的情况

环境：Audiokinetic Launcher + Wwise 2025.1.11.9262，工程名 ParkLakeAmbience（不含中文），平台 Windows。

工程层级结构：

Containers（该版本的容器层级，旧称 Actor-Mixer Hierarchy）
├── amb_parklake_loop_01          Sound SFX，2D，Loop=True
├── RC_BirdChirp                  Random Container ×3 变体，3D，衰减 ATT_Park_3D
├── RC_WaterBird                  Random Container ×3 变体，3D，衰减 ATT_Park_3D
└── RC_LeavesGust                 Random Container ×3 变体，3D，衰减 ATT_Park_3D

Attenuations
└── ATT_Park_3D                   0 m = 0 dB（对数） → 50 m = -96 dB

说明：Wwise 2025.1 中，过去名为 Actor-Mixer Hierarchy 的层级在 Project Explorer 里已改名为 Containers。工程文件的 .wproj 中也只声明 Containers，无 Actor-Mixer Hierarchy。

（a）基底的持续循环

对 amb_parklake_loop_01 启用循环（属性 IsLoopingEnabled = True），使其无限循环播放；Playback Limit 保持 1，确保基底只有一路。

基底刻意不启用 3D、不绑定 Attenuation——它的功能是包围听者，不应有方位。

（b）Random Container 随机触发

三类随机声各建一个 Random Container，容纳各自的 3 个变体。为什么是 3 个变体：Random Container 的价值在于"同一事件听起来不像同一个文件"，只有 1 个变体时随机触发会退化为机械重复。

（c）3D Positioning 与距离衰减

三个 Random Container 均启用 3D 空间化（3DSpatialization = 1），并共同引用 Attenuation ShareSet ATT_Park_3D：

参数 值
曲线类型 对数（Log3）
起点 0 m → 0 dB
终点（Max Distance） 50 m → -96 dB

效果：听者在 0–5 m 内几乎满音量，随后按对数规律衰减，50 m 外基本不可闻。

定位策略的对照——这是本设计的核心表达：

对象 定位 Attenuation 设计理由
基底环境声 2D 不绑定 包围感，无方位
3 个 Random Container 3D ATT_Park_3D 事件有明确来向与距离

（4）对作品的自我评价

做得比较好的地方

  1. 设计逻辑自洽。2D / 3D 的分工不是为凑技术点，而是从场景的"包围 vs 方位"关系推导出来的，技术配置与设计意图一一对应。
  2. 选材有量化依据。对源素材做了采样率、动态范围、瞬态事件、频段分布的实测，用数据证明了双层叠加的必要性，而不是"听着差不多"。
  3. 格式规范经自动化校验。10 个资产全部通过脚本校验，不靠肉眼确认。
  4. 过程可复现。仓库中保留了源素材测量记录、处理参数、校验脚本与 Wwise 工程，任何人可据此复现整个作品。
  5. 工程与生成物的边界清晰。.gitignore 规则经 check-ignore 逐条核对，仓库不含缓存与 SoundBank。

不足之处

  1. 素材全部来自素材库，缺少实地录音的空间细节。真实录音的场地感、空气感是合成难以完全替代的；
  2. 基底主层本身偏低频（<200 Hz 占 71.3%），虽用副层与 EQ 补偿，但补不出原本不存在的高频细节；
  3. 声场只有 2D 基底 + 少量 3D 事件，未做遮挡（Obstruction）、混响区域（Room/Portal）、动态混音等更复杂的交互设计；
  4. 随机声变体偏少，每类 3 个在长时间聆听下仍可能被听出循环感。
  5. ⬜ 待填：你自己的其他感受

改进方向

  1. 采用「真实录音打底 + 合成素材补变体」的混合方案，兼顾空间真实感与变化量；
  2. 引入 Wwise 的 Room / Portal 与 Obstruction，让"湖对岸的声音"真的被树丛衰减；
  3. 用 RTPC 驱动动态混音，例如按玩家与湖岸的距离调整水声占比；
  4. 每类随机声扩充到 6–8 个变体，并引入 Weight 与 Shuffle 策略控制分布。

与平时作业调研的呼应

平时作业中分析过 AIGC 在游戏音频中的"权利与合规"风险与"质量天花板"问题。本次期末作品实际使用 AIGC 与素材库后，这些判断被具体化了：

  • "平均可用率 + 修复成本"才是评估标准——本次 9 个随机声的切割边界前后返工两轮，正是"修复成本"的真实体现；
  • AIGC 是素材供应商，不是艺术决策者——素材能否用、怎么用、如何组织成有意义的声景，完全依赖人的听觉判断与结构设计；
  • 真实素材与合成素材各有其位——长时环境声用真实录音，短促功能性音效用合成或库素材，这个分工比"全用某一种"更可靠。

四、遇到的问题与解决

# 问题 原因 解决
1 AIGC 长音频工具 Stable Audio 注册被阻断 地区 IP 限制，非操作问题 改用免费素材库 + 双层叠加，并以实测数据论证选材
2 基底源素材峰值仅 -31 dBFS 上传者电平留了大量余量 整体增益 +25 dB 提至 -6 dBFS（增益线性，不改变信噪比）
3 基底偏低频，"树叶沙沙"不足 单条素材频段分布不均 叠加高频层（副层 2–8 kHz 占 62.2%），并做频段分工 EQ
4 循环点接缝可闻 首尾能量不连续 "尾巴叠头" 2 秒等功率交叉淡化，实测接缝跳变 0.79×
5 多个随机声切在声音中间 仅按能量包络选窗，未考虑声音边界 引入静音间隙检测（20 ms 包络 + -30 dB 阈值）
6 随机声中混入金属碰撞声 窗口落在拍翅结束后的低能量残留区 引入频谱音调性分析定位并避开
7 Wwise 中找不到 Actor-Mixer Hierarchy Wwise 2025.1 已将其更名为 Containers 查 .wproj 确认层级列表后按 Containers 操作
8 导入音频后工程未保存 音频复制进 Originals/ 但对象仅在内存 及时 Ctrl+S，并核对 .wwu 中是否出现对象定义
9 .gitignore 中 Originals/Plugins/ 不生效 带内部斜杠的规则锚定在 .gitignore 所在目录，实际路径多一层 改用 **/Originals/Plugins/，暂存体积从 8.48 MB 降至 1.95 MB
10 衰减曲线不生效（无距离变化） 从工厂模板复制时 CurveToUse="None"（该模板走物理模型） 改为 CurveToUse="Custom"，曲线生效为 0 m→0 dB、50 m→-96 dB
11 Wwise 面板误关后无法恢复 布局被存成"修改版工厂布局"，Layouts → Designer 加载的仍是坏版本 移走 Layouts\7\Modified Factory Layouts，回落到原始工厂布局

五、反思与总结

关于技术

本作品最关键的技术点是循环点处理与2D/3D 分工。前者决定环境声是否"经得起长时间听"，后者决定声场是否有空间逻辑。二者的共同点是：它们都不是软件里点一下就有的东西，而是需要先想清楚"要什么效果"，再倒推实现路径。

另一个体会是**"能测量就不要靠感觉"**。素材的电平、频段、切割边界都可以用数据判断；把主观判断压缩到最小范围，剩下的才交给耳朵。这在时间紧张时尤其重要——不可能把每个文件都反复听二十遍。

关于 AIGC 用于声音设计

实操后对平时作业的结论有两点修正：

  1. AIGC 在"短促、形态明确"的音效上确实可靠（鸟鸣、拍翅、风声这类几秒的事件），但在长时持续的环境声上明显偏弱——这也解释了为什么行业里 AI 音效落地的第一个场景往往是占位资源与变体生成；
  2. "生成"不是最贵的一步，"筛选与修复"才是。真正耗时的是判断哪一条能用、切割边界在哪、要不要返工。

关于局限

本作品最大的遗憾是没有实地录音。真实录音的场地感、空气感、随机细节是素材库与生成模型都难以完全替代的。如果重做一次，我会先带手机去公园录 10 分钟环境底噪，再以此为基底、用素材库补齐事件层——真实打底、合成为辅，这也是目前最务实的工作方式。
